# The Python stack

Distilled from Neon Rain (R-001, R-015, R-017, R-018). Stamping a Python project copies `starter/`
to the repository root (a `starter/` path below is the same path at a stamped project's root) and writes `stacks/python/PRESENT`; `scripts/gate.sh` then runs
`stacks/python/gate.sh`. The core's own checks are already Python, so the stack adds the rules for
a project whose *product* is Python, which the maintainer cannot audit by eye the way he audits
Java or C#: **the tests are the audit** (Neon Rain R-015).

| Rule | What it is | Held by |
| --- | --- | --- |
| Toolchain | Python 3.12 in a venv made once per session; `pyproject.toml` is tool configuration only, not a package | `scripts/gate.sh` |
| Fast loop | `.venv/bin/pytest` (or the core's `scripts/fast.sh` while there is no product code), under 30 s; no data, no network; `docs/AGENT.md`'s metrics table counts documentation and source lines, so any lane that adds code makes `test_metrics` red until the coordinator runs `python3 -I scripts/metrics.py --write` at landing: a worker leaves that file alone; `scripts/fast.sh` runs the system `python3 -I` (here 3.13, built without tkinter) while pytest and mutmut run the venv's 3.12, so a test module that imports tkinter guards the import (`importlib.util.find_spec("tkinter")`) and skips "no tkinter", then skips "no display" where `Tk()` raises `TclError`; the widget tests run under `xvfb-run -a .venv/bin/pytest test/solarpunk/test_ui*.py` (J-025) | AGT-02 |
| Dependencies | `requirements.in` holds the direct dependencies with one line of reason each; `requirements.lock` is compiled from it with hashes; installed with `pip install --only-binary :all: --require-hashes -r requirements.lock`; never `pip install <name>` in a session | `starter/scripts/checks/imports.py`: an import not in the lock fails |
| Cooldown | the lock is compiled with `--exclude-newer` seven days back; a version younger than that does not enter | the compile command in `requirements.in`'s header |
| Mutation | mutmut over the product and the checks; every survivor killed or written up in `docs/MUTATION.md`; `scripts/survivors.py` refuses an unexplained one; `# pragma: no mutate` regions are Ghost's alone to grant (C-018); a lane's survivors in another module are that module's, not the lane's (the leaf had none of its own tests until 1.8, J-013); keep SQL and other literal strings in module-level constants, since mutmut leaves module level alone and a letter-case mutant of a SQL string is always equivalent (J-008); a UI string (an argparse help) is a mutant no test can catch, so keep them few and tested (J-014); a module-level load runs before a mutant is switched on, so data a module reads at import is covered only through its parse function's own tests (J-016); a function no test may run (one that touches the host: `install`, `remove`) leaves "no tests" mutants that `scripts/survivors.py` accepts (J-018); read `build/mutmut.log` with `tail -c 300`, the spinner writes one long line (J-019); a mutant on a line only a Tk window reaches is a display-only survivor (`docs/MUTATION.md`'s class), and mutmut's own verdicts under xvfb are not to be trusted: the recipe is one pytest run per window mutant with `MUTANT_UNDER_TEST=<name>` set, inside `mutants/`, under xvfb (J-026) | `gate.sh` |
| Readability | type hints on every function (ruff ANN); no bare except; functions under 40 lines; no comprehension over three clauses; no `*args`/`**kwargs`; no decorator magic; no operator overloading; a docstring per function with a concrete input→output example; `test_*` methods are exempt from the docstring rule, `setUp` is not; the checks read git's file list, so a new file is `git add -N`'d before `scripts/checks/readability.py` or `imports.py` sees it (four lanes missed this, Tune-up pass 1); an Enum's members are compared with `assertIs`, and a leaf Enum has a test that its members differ (J-020) | ruff plus `starter/scripts/checks/readability.py` |
| The blind mirror | a contract's numbers are reimplemented from the contract text alone by an agent that has not seen the code, and compared by a test; every number the maintainer is asked to trust has a ten-row example he can check by hand | the project's mirror test |
| Isolation | every script that reads supplied data runs with `python3 -I`; a SQLite connection is used only on the thread that opened it, so a server opens its own per request (J-017); a fake SMTP server compares verbs case-insensitively, since smtplib's casing differs between 3.12 and 3.13 (J-019) | the recipes |
| Dependency updates | `docs/DEPENDENCY-REVIEW.md` (C-035). Fetch both sides without running anything: `pip download <name>==<version> --no-deps --no-binary :none: --only-binary :all: -d <archives>/old/` (wheels only; a sdist's setup.py is code), then `python3 -I scripts/review_scan.py --unpack <old>.whl <new>.whl "$REVIEW"` (a zip unpacked without links, special members, owners or modes; never `unzip` by hand); a `.pth`, `sitecustomize.py` or `usercustomize.py` the wheel adds or changes is a scan hit and never routine; the audit is `pip-audit -r requirements.lock` and OSV.dev on `PyPI:<name>`; provenance is the PyPI attestation (`https://pypi.org/pypi/<name>/<version>/json`, `urls[].attestations`), compared with the version before: the red flag is an attestation the prior version had that this version lacks, or a different publisher identity inside it (PyPI does not publish the uploader in a form a script can compare); the lock's `--exclude-newer` is the cooldown | `scripts/review_scan.py`, `scripts/checks/imports.py`, `docs/REVIEWED-VERSIONS.md` |
